# Technical architecture

The static client uses Vite, TypeScript and React for application state and accessible overlays, Three.js for a full 3D renderer, Rapier 2D for planar rigid-body integration, Web Audio for original synthesis and localStorage for progression. Direct Three.js keeps the high-frequency renderer outside React reconciliation; React snapshots update at about 20 Hz. There is no backend or runtime network dependency after the build's resources load.

`src/game/core.ts` owns the dynamic vehicle, collision surfaces, forces, pressure, checkpoints and completion. `src/game/levels/index.ts` explicitly orders ten numbered mission files. The FAULTLINE files author stage sequences through `faultline.ts`, which produces the same Level/Track geometry used by both physics and rendering. `wind.ts` samples bounded, deterministic forces. Collapse activation, gate activation and platform phase are restored with checkpoint state; collapsed segments are excluded from both colliders and suspension probes. `config.ts` names all principal tuning parameters. `input.ts` merges keyboard state and independently captured pointer IDs. `save.ts` owns local data and best records. `audio.ts` synthesizes state-responsive motor, wind, fan, thrust, impact and milestone sounds.

`src/render/vehicle.ts` constructs the original car and its mechanical animation pivots. `environment.ts` constructs one theme at a time using shared geometry, material batches and instancing. `engine.ts` manages WebGL, environment reflection, lighting, camera, quality and lifecycle. `effects.ts` reuses a fixed particle pool. `src/ui/App.tsx` coordinates the fixed-step loop and the complete menu/HUD/pause/failure/result/settings flow.

The accumulator advances physics at 120 Hz and clamps background catch-up. When a previously unseen teaching hint is waiting for its first correct input, game time slows to 55%; the physics step remains fixed. Visibility or window focus loss releases momentary input and pauses gameplay. The camera remains world-up, smooths its movement, looks ahead by signed velocity and expands for airborne or loop regions.

The original vehicle is built from lofted and parametric surfaces rather than imported GLB, allowing deterministic asset creation and independent animated mechanical groups without a Blender installation. A separate GLB export provides a portable rest-pose asset. Runtime geometry avoids duplicate model downloads. No screenshots or reference photos are used as car textures.

Quality controls adjust pixel ratio, shadow availability/resolution and particle density. Auto initially selects a conservative profile on touch devices and can fall to Low after sustained poor measured rendering. Critical car shape remains intact at every quality. Scene changes explicitly dispose geometry, materials and textures; the persistent car and reflection environment are reused.

Only development builds expose `window.__ROADSTER__`, the state/input/fixed-step/inspection/profile bridge. Full-course QA drives the actual game core with legal player input. The bridge cannot set arbitrary transforms, pressure, checkpoints or completion. It is excluded from production by Vite's compile-time DEV constant. Replays use `tests/replay-policy.ts`; the production bundle does not import that file.

The camera identifies the next physical track using the core's current track index. During gaps and ceiling releases it frames the car and a forward lower landing surface, instead of selecting a previously passed platform. Ground contact loss emits a brief warning; bounded landing and finish camera motion respect the reduced-motion setting. Development overlays separately visualize the actual summed suction and thrust forces, rounded collision boundary, wheel contacts, surface normal and checkpoints.

Inverted driving lowers the camera observation height while keeping its world-up axis unchanged, avoiding the ceiling deck hiding the car. Canyon cantilever columns sit behind the driving plane so upper decks do not visually block lower routes. The custom pitch pad consumes native touchmove with a scoped non-passive listener; Pointer Events continue to own the actual input state and cancellation. The listener is removed when the pad is unmounted or the control mode changes.
