# Roadster 玩法调研与优化策略

调研日期：2026 年 10 月 18 日。

## 1. 建议采用的方向

将现有游戏发展成**以真实道路设施为场景、以喷气和吸附为特色的物理驾驶闯关游戏**。近期优先增加道路事件、路线奖励和时机判断；移动集装箱作为下一步的代表性玩法；收集材料搭路作为后续局部实验。

关卡长度先增加约 40%–70% 的有效路线，以新增挑战段延长体验。不要仅扩大障碍间距，也不要通过重复等待拖长流程。这里的比例是设计建议，不是已经验证的最优值。

玩家的主要循环应形成：观察前路 → 选择速度、路线或出发时机 → 驾驶／喷气／吸附 → 收集奖励并处理着陆 → 在检查点恢复 → 进入新的组合挑战。新增机制应尽量复用现有操作。

用户提到的“搭”尚未指定具体游戏，本调研分别考虑了搭桥、搭路和搭乘移动载体三个方向，没有将其认定为某一款游戏。

## 2. 当前项目的问题与可利用基础

本节依据当前源码、设计文档及仓库内既有验收产物，不是本轮重新试玩的结果。

| 方面 | 已确认的现状 | 对优化的影响 |
| --- | --- | --- |
| 基础操作 | 加速、制动／倒车、有限气压喷气、长按吸附、空中俯仰已经具备 | 可以用关卡组合扩充玩法，不必首先增加按钮 |
| 关卡结构 | 三关分别围绕断桥长跳、重力环、两次高空倒立释放展开 | 每关已有主题，应在主题之间增加道路事件，而不是复制相同大跳 |
| 障碍 | 三关分别有 3、2、2 个障碍定义，均为固定矩形碰撞体，外观统一采用工业块体 | 外形辨识和行为变化都不足；仅换成汽车外观仍不能显著增加决策 |
| 收集与资源 | 未发现关内收集物机制；气压主要在检查点补满，满压持续喷气约 4.35 秒 | 可增加少量气压补给和可选收集目标，让玩家主动选择飞行轨迹 |
| 成绩 | 已有完成时间、失败次数、生命值参与的关卡星级；翻转、滞空等已有统计 | 关内收集星星需要与结算星级分开表达，避免混淆 |
| 道路物理 | 二维刚体配三维渲染；深度车道由路线决定，玩家不能自由左右换道 | 汽车阻挡应通过跃过、等待、上层路径或刹车处理，不能要求玩家侧向绕车 |
| 可驾驶表面 | 悬挂探测依赖初始化后的固定轨道线段；障碍碰撞体没有对应轮胎承载面 | 车顶和移动集装箱若要供车辆行驶，需要真正加入可驾驶表面 |
| 恢复 | 已有检查点、满血和气压恢复、倒立复活保护、下层恢复平台 | 延长关卡时可沿用；新机关需要安全的复活位置和运动阶段 |

仓库中 2026-10-17 的浏览器输入重放记录显示，三关分别用时约 **17.70、14.61、37.64 秒**，均完成且没有失败。这是自动反馈策略的一条通关路径，不能代表新玩家平均用时，也不是本轮重新运行结果。它仍说明前两关存在很短的有效通关路线。配置的三星时间阈值为 27、28、58 秒，不能将这些阈值当成实际游玩时长。

## 3. 十款参考游戏：借鉴机制及适配方式

竞品事实以开发者、发行商官网或其商店说明为依据。下表的“适配建议”是本项目的设计判断，不是竞品官方结论。本轮没有逐款实机试玩或完成竞品视频的逐帧分析。

| 参考游戏 | 官方资料确认的机制 | 本项目的适配建议与取舍 |
| --- | --- | --- |
| [Hill Climb Racing](https://fingersoft.com/games/hill-climb-racing/) | 物理驾驶、收集金币、特技奖励、燃料约束 | 借鉴“路形＋资源”的持续判断；本项目采用气压补给即可，暂不再加一条燃油消耗 |
| [Hot Wheels: Race Off+](https://www.hutch.io/our-games/hot-wheels-race-off/) | 物理特技赛道，包含加速设施、回环和跳跃 | 借鉴有节奏的赛道组合，让普通路段为后续大动作蓄势；车辆收集和升级不是近期重点 |
| [Trials Rising](https://www.ubisoft.com/en-us/games/trials-rising) | 摩托平台闯关、精心布置的赛道、挑战任务和对手幽灵 | 借鉴同一套驾驶操作应对不同地形与任务；个人幽灵可以后置，多人和大型成长系统目前收益有限 |
| [Jet Car Stunts](https://trueaxis.com/jetcarstunts.html) | 喷气特技驾驶、空中环、浮空平台、螺旋道路及平台／计时玩法 | 与现有喷气最贴近：增加空中收集轨迹、精确落点和气压选择，区分“能过关”和“过得漂亮” |
| [Distance](https://store.steampowered.com/app/233610/Distance/) | 驾驶与跑酷结合，可跳跃、旋转、飞行、倒立驾驶并寻找捷径 | 与吸附和姿态控制最贴近：把地面、倒立、高低路线连成连续驾驶体验；先围绕既有能力做组合 |
| [Clustertruck](https://store.steampowered.com/app/397950/Clustertruck/) | 在高速移动卡车上跳跃，加入摆锤等危险和可解锁能力 | 借鉴“移动载体也是地形”；本项目先采用有规律的集装箱承载台，不照搬大量不可预测卡车混战 |
| [Earn to Die 2](https://www.notdoppler.com/earntodie2/) | 多层路线跨越高架、隧道、工厂，车辆可受损并有升级 | 借鉴道路和工业环境的路线叙事：交通事故段、维修段、货运段；暂不引入武器和升级刷取循环 |
| [Shortcut Run](https://voodoo.io/games/shortcut-run) | 沿途收集路板，用板搭桥并抄近路 | 借鉴“资源用于改变路径”；可实验固定槽位自动铺桥，保留材料不足时的普通路线 |
| [Bridge Race](https://apps.apple.com/us/app/bridge-race/id1543845882) | 收集同色方块，修建桥梁并与对手争先 | 借鉴可见的收集—消耗—通行反馈；不必加入多人抢材料，也不必把驾驶改成步行收集 |
| [Poly Bridge 3](https://store.steampowered.com/app/1850160/Poly_Bridge_3) | 建桥解谜、液压桥、多层桥以及先建造再验证通行的过程 | 适合作为搭建方向的边界参考；自由节点、预算和结构应力会形成另一套主玩法，近期不采用 |

其中最适合当前项目的组合是 **Jet Car Stunts／Distance 的车辆平台闯关，加上 Clustertruck 的移动落脚点**。Shortcut Run 的材料铺路适合作为可选扩展，先验证一个段落是否有趣。

Supersonic 的[开发案例](https://supersonic.com/learn/case-studies/bridge-race/)和[机制分析](https://supersonic.com/learn/blog/5-trending-hyper-casual-mechanics-taking-over-the-top-game-charts/)说明 Bridge Race 曾把堆叠进一步转化成建桥通行。这支持“收集物有明确用途”的借鉴方向；这些发行商历史案例不能证明相同机制在本项目一定提高留存。

## 4. 延长关卡：增加完整事件段

长度应以有效驾驶路线和挑战段衡量。第二、三关包含环形、反向行驶和高低落差，终点横坐标不能代表实际路线长度。

第一轮建议有效路线增加约 40%–70%，并以以下时长作为调校起点。时长是顺畅通过、包含少量正常观察时间的目标，不是硬性限时，也不是已经取得的测试结果。

| 关卡 | 既有自动重放用时 | 调校目标 | 新增内容重点 |
| --- | --- | --- | --- |
| 第一关 Ignition | 约 18 秒 | 约 28–35 秒 | 事故车辆、拖车坡板、气压收集和两段长跳之间的中间挑战 |
| 第二关 Inversion | 约 15 秒 | 约 24–30 秒 | 环后短倒立支路、一道有预告的动态障碍、恢复路线与奖励路线 |
| 第三关 Skyfall | 约 38 秒 | 约 55–65 秒 | 一段横移集装箱、一段升降接驳以及原有的高空释放组合 |

新玩家可能明显更慢；待真实手动体验后再决定目标是否合适。若关卡长度增加但主要时间花在等机关，应缩短等待而不是继续加路。

每关按“进入状态 → 单项挑战 → 安全恢复 → 组合挑战 → 标志性收尾”安排。新增机制第一次出现时单独展示，随后改变速度、落点或奖励位置，最后与已学会的能力组合。同一时间避免同时教学新的移动机关、新资源和新的吸附规则。

每个主要挑战之前设置安全检查点；主要挑战之后留出恢复控制、看清前路的空间。检查点间隔可先按约 10–20 秒有效驾驶调校，简单段允许更长。检查点应与挑战位置匹配，不按等距离机械放置。

## 5. 用真实道路物件形成不同驾驶行为

“真实道路”主要体现在物件外观、摆放原因和行为可以理解。喷气、倒立和空中道路继续保留，可将场景解释为封闭试验道路、维修高架和工业货运区。

| 物件 | 应产生的行为 | 初期实现边界 |
| --- | --- | --- |
| 锥桶、轻型塑料围挡 | 提前提示施工区，轻碰提供反馈 | 低惩罚或只作提示；避免小物件导致翻车或大量扣血 |
| 抛锚轿车、事故车 | 提早判断，短喷气跃过，或者选择坡板上方路线 | 外形要能识别；可越过的高度与气压消耗需实测 |
| 平板拖车、装卸坡板 | 从地面驶上坡板，再从车顶或货台跳出 | 需要匹配可驾驶轮廓，不能只在原矩形碰撞体外包一层模型 |
| 大巴、重型货车 | 作为明确不可直接冲撞的大型障碍，提示改走上层或等待通行 | 大型车辆前必须给出可见的合法解法 |
| 道闸、升降限高架 | 制动、观察开启时机、通过后再加速 | 运动规律固定，有灯光和动作预告，不在车辆进入后突然无预警关闭 |
| 慢行工程车 | 判断相对速度，选择减速跟随或喷气越过 | 先做单车固定往返，避免建立完整交通系统 |
| 吊装集装箱 | 可同时成为空中障碍与接驳平台 | 先采用稳定、可预测运动，悬挂结构和停靠点在视觉上可辨认 |

当前没有横向转向，因此“前车挡路后向左／右变道”不能直接成立。首轮设计以纵向追赶、跨越、上下路线和等待窗口为主。汽车也不宜全部复制当前“触碰即扣血”的定义：车顶若是可驾驶路线，正常驶上车顶应按路面处理，撞上车身才按撞击处理。

## 6. 收集系统：先让奖励改变路线选择

建议首轮只有两类收集物。

**第一类是每关三枚挑战星。** 三枚分别放在安全可见的教学位置、需要控制姿态的高位、需要额外判断的支路或移动平台上。主线无需集齐即可通关，首次通关继续解锁下一关。星星服务于探索和完成度，不兑换基础动力。

**第二类是少量气压罐。** 放在需要额外喷气的奖励路径入口或中途，让玩家决定是否承担风险换取后续操作余量。可先以每罐恢复约 20–25 点气压试调，约相当于 0.9–1.1 秒连续喷气；这些是候选参数。普通主线的必需气压应能从检查点获得，不能因为漏掉可选星星而无法完成下一次必跳。

星星布局应形成明确意图：一枚引导合理的跳跃弧线，一枚诱导延迟喷气或精确着陆，一枚要求离开最快路线。若全部排在道路正中，玩家只是顺便捡到，玩法增量很小。

现有结算已经用星级表达表现，建议将旧评分在界面上改用“通关／银牌／金牌”视觉，时间、生命和失败条件先沿用；关内星星明确显示“收集 0/3”。改名不要求重写评分公式，也不应把“全收集”和“最快通关”绑定成唯一目标。

恢复规则保持简单：挑战星在本次关卡中收集后，检查点重试不丢失；通过整关后记录累计收集到的星星身份。气压与气压罐则恢复到检查点对应状态，避免倒车反复吃同一个罐子无限补气。整关重开恢复本局收集物，但不删除历史完成度。

首轮先不加通用金币商店。金币若不能带来有意义的选择，只会增加界面和数值；性能升级还可能让既有关卡难度失去一致性。

## 7. 动态道路：以移动集装箱为重点

动态道路应当改变落点、接触速度或发车时机。背景吊机摆动、路板播放动画但碰撞位置不变，都不足以构成这类玩法。

| 类型 | 玩家需要判断什么 | 推荐顺序 |
| --- | --- | --- |
| 水平移动集装箱 | 何时上车、是否减速、何时从另一侧离开 | 第一种原型；运动沿当前驾驶平面的水平轴发生 |
| 升降货台 | 等待到站、控制驶入速度、在合适高度离开 | 水平平台稳定后加入，先做单台 |
| 翻转桥板 | 当前坡度、接桥时刻、能否借其起跳 | 后续机制，先验证倾斜表面的稳定承载 |
| 吊装金属板／箱体下表面 | 何时吸附、随平台移动后何时松开 | 进阶组合，承载与吸附验证后再做 |
| 受压后延迟塌落的路板 | 进入前决定速度、进入后连续通过 | 更后置，需要清晰的预告和恢复方案 |

首个移动平台可先采用约两到三倍车长的有效承载面、两端短暂停靠、规则往返。尺寸、速度和周期都应由手动体验调校，不能由本报告直接定死。初次等待目标控制在约 2–3 秒以内；熟练玩家应能通过提前观察连续通过。

在驾驶平面之外仅沿深度轴来回移动的平台，会要求新的横向交互和碰撞规则，首轮避免采用。视觉上仍可保留三维吊装场景。

移动平台必须满足以下实际行为：车轮能识别平台；静止车辆随平台正常移动；平台运动速度参与接触和着陆计算；平台视觉与碰撞一致；暂停时机关停止；重试不会将车辆放进移动物体。向上移动的平台也不能因为自身速度造成不合理的重落地伤害。

镜头是动态挑战的一部分。先让玩家看见等待区、平台运动范围和对岸落点，再要求作出决定。预告距离应随接近速度增加：例如以 20 米／秒接近、希望提供 1.5 秒观察时间，单是反应距离就约 30 米，还需要另留制动距离。这是设计估算，实际安全距离取决于游戏中的刹车、坡度与喷气状态。

星星路径只能提示方向，不能承诺无论何时起跳都安全。若星星位于动态落点附近，应放在对合理通过时机仍可收集的位置，避免用固定星星弧线误导玩家跳向已移走的平台。

## 8. “搭”类玩法的选择

| 方案 | 带来的乐趣 | 代价 | 当前建议 |
| --- | --- | --- | --- |
| 搭乘移动载体 | 观察、追赶、减速、落地和接驳形成连续驾驶 | 需要移动承载面和镜头配合 | 优先；与现有游戏最贴合 |
| 触发预制桥 | 车辆驶过压板后桥面展开，形成通行窗口或捷径 | 新增触发机关与桥面状态 | 可作为短段实验，学习成本低 |
| 收集路板、自动铺桥 | 收集有实际用途，玩家选择资源换路线 | 增加资源和路径规则 | 后续只做一个可选捷径，验证价值 |
| 自由搭桥 | 玩家自行设计形状并验证承载 | 建造界面、编辑交互、结构规则与大量内容需求 | 近期不采用，容易分散驾驶主线 |

如果实验自动铺桥，建议在固定桥槽显示虚线预览和所需路板数。材料足够后驶入即可自动搭成；不足时明确保留普通道路，不让玩家进入无解状态。集齐材料后道路应真正变化，而不是只在结算里加分。

桥面应在车辆驶入前形成可驾驶实体。检查点重试同时恢复该段桥面与材料的对应状态，防止材料已扣而桥不存在。这个实验不需要自由拖拽建造界面，也不需要新增搭建按钮。

## 9. 三关如何各自形成特色

### 第一关：事故与施工道路

用道路物件引入跳跃和收集，把原有两次长跳作为主要节奏支点。建议顺序为：

起步与低风险星星 → 锥桶预告和抛锚车 → 拖车坡板与高位星星 → 安全补给／检查点 → 第一处断桥 → 短维修道路和可选收集 → 最终长跳 → 宽落地终点。

先不安排必须等待的移动平台。新增障碍的喷气消耗必须计入长跳前的气压预算，不能延长道路后使主线依赖反复重生补气。

### 第二关：吸附试验道路

保留重力环，在环前提供一次普通障碍判断，在环后给玩家明确的路线选择：普通下层路线容易通过；短倒立支路更难，但能取得一枚挑战星。两条路线最终汇合，再通过一道可预判的升降限高架进入终点段。

支路不能跳过必须激活的检查点，也不能让下层恢复路线成为无意义的惩罚。第一次学习吸附时不同时加入移动吸附面。

### 第三关：峡谷货运接驳

保留两次高空倒立释放，将其中一次长直连接段改为货运接驳：先在宽等待区看清水平移动集装箱，再驶上或跳上平台，适当减速随行，驶向对岸后继续加速。随后使用单台升降货台或固定高低路线完成第二段组合。

两种移动平台第一次出现时分开安排。最后仍以已有的姿态控制和着陆作为收尾，避免在最难落点叠加未介绍的新机关。

若水平平台单独体验已足够丰富，升降货台可留到后续，不要求首轮一定把两类都塞进第三关。

## 10. 优先级与推进方式

| 阶段 | 内容 | 目的与完成依据 | 相对工作量 |
| --- | --- | --- | --- |
| 第一阶段 | 扩写第一关；加入事故车、坡板等道路障碍；三枚挑战星和少量气压罐；区分收集与成绩 | 先证实更长且有路线奖励的关卡值得重玩，主线仍可独立完成 | 中 |
| 第二阶段 | 单个水平移动集装箱原型，处理承载、相对速度、镜头、暂停和复活；确认后放入第三关 | 证实“观察—上车—随行—离开”本身有趣且稳定 | 中高，是本轮价值最高的技术扩展 |
| 第三阶段 | 第二关的可选倒立支路和一种动态道路障碍；第三关增加一种变化组合 | 增加既有操作的组合深度，逐关调校长度与难度 | 中 |
| 后续实验 | 固定槽位的收集铺桥；个人最佳幽灵；少量挑战任务 | 依据前面体验决定是否继续投入 | 铺桥中高；其余取决于范围 |

优先级同时考虑收益与依赖。收集机制和真实道路障碍比较容易形成可玩的整关；移动集装箱需要先解决承载，不能按“给模型加动画”的工作量估计。

现有源码足以支持局部扩展：先给障碍区分外观和行为，增加少量收集物定义，再为移动路面补上共享的运动状态与可驾驶表面。无需为本次优化预先建设通用机关编辑器、复杂事件系统或完整交通模拟。

改动关卡路线后，旧最佳时间和新路线不能直接混排。应保留旧成绩数据，为修改后的关卡使用独立的成绩版本，避免清空用户存档或显示无法公平比较的纪录。具体存储改法在实施时按现有结构作最小修改。

## 11. 如何判断优化是否有效

实施后先做针对性物理和规则验证，再用实际手动体验判断乐趣。自动通关只能证明存在可行路线，不能证明新机关好玩或触屏舒适。

必要规则验证包括：不收集星星也能通关；必需跳跃的气压充足；收集不重复发放；移动平台的碰撞、承载和画面一致；暂停与复活安全；新支路保持检查点顺序；原有喷气／吸附互斥和倒立恢复没有回归。

手动体验重点记录：

1. 玩家在碰到机关前，能否判断“这是挡路车辆、可站立平台还是装饰”？
2. 玩家第一次失败后，能否说清原因，并在下一次调整速度、起跳时机或姿态？
3. 不追求收集时流程是否顺畅；追求三枚星时是否出现不同驾驶选择？
4. 移动平台是否让玩家主动制动与观察，而不只是停在原地等很久？
5. 延长后的关卡能否回忆出不同事件段，还是只觉得同一种跳跃重复更多？
6. 手机横屏时能否同时看清车辆姿态、平台和落点；操作是否过度要求多指同时保持？

不必为本轮策略建设额外数据平台。可先在现有重放结果之外记录少量人工体验笔记与分段用时；若出现反复失败，再针对具体段落修正。
