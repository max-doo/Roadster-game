# 环境资产与实现约束

本文记录当前机库与三关场景的资产来源、表现方法和验证边界。视觉方向沿用 [PRODUCT.md](../PRODUCT.md)、[DESIGN.md](../DESIGN.md) 和[场景视觉方向](scenery-direction.md)：暖白车辆、石墨色与钛金属设施构成航天汽车试验场，青色表示吸附，橙色表示推力与警告。车辆、路面、障碍边界和落点应先于背景细节被识别。

## 场景构成

展示机库采用运行时生成的三维建筑与设备。约 4.65 米长、2.1 米宽的车辆置于直径 12.4 米的低转台上；金属地坪、结构肋、吊装设备和试验台建立空间尺度。高架廊道有落地支撑、开放检修楼梯、护栏与仪表屏，设备舱使用铝百叶、检修五金和琥珀色灯带。右侧暖色开口提供远处亮部，青色廊道灯引导视线。较低、较近的展示镜头突出车辆，窄横屏使用单独的近距离构图。机库设备均为装饰。

| 关卡 | 当前表现方法 |
| --- | --- |
| 沙漠试验场 | 连续沙丘、分层侵蚀山脊、扫描沙地与岩石材质形成自然地表；试验棚、太阳能遥测设备和测量标杆提供尺度，天空全景与暖色距离雾衔接地平线。 |
| 重力实验室 | 石墨色围护、冷色顶光、三维桁架和结构环形成封闭空间；凹入维护舱、观察窗、顶管和服务通道标线区分建筑表面，降低重复构架密度以保留路线轮廓。 |
| 峡谷跨越区 | 多层地质轮廓、岩壁扫描材质、桥架及航空设施形成真实视差；远处山体由距离雾降低对比，天空全景提供云天，另有不同深度的程序化透明云带。低处装饰岩块避开主要行驶与落点视线。 |

事故轿车与厢式车使用连续车身轮廓、实际轮拱、独立车窗、保险杠和灯具。第一辆低矮事故车的可见外壳贴合道路坡度与轮胎接地点，并通过局部压缩约束在既有碰撞体上边界内；路线和碰撞体保持原值。货箱保留波纹板、角件和锁杆，拖车保留车架、轮组与标志灯。升降门具有独立活动面板、导柱、横梁和检修梯，危险条纹限制在面板表面内。移动门与其他移动物体通过既有 `motionAt` 及物理世界时间更新，使视觉位置与碰撞运动一致。

## 三维、PBR 与全景的分工

本项目采用混合方法，是基于跟随镜头、三关路线和网页运行成本的取舍。近景障碍、可行驶结构和中景建筑需要遮挡、视差、接触阴影与明确轮廓，因此保留三维几何；混凝土、岩石和沙地使用 PBR（基于物理的渲染）扫描贴图区分表面。近景混凝土保留与颜色、粗糙度对齐的 UV 法线贴图。自然地形的颜色与粗糙度使用完全相同的世界空间三向投影坐标，减少缩放拉伸；不匹配该投影的 UV 法线贴图已停用，地表起伏由几何表达，另以低强度地层和侵蚀变化连接不同尺度。

天空负责远处云层和光色。全景映射在天空球内侧，天空球随镜头平移，避免天空产生近景视差；山体与建筑仍留在世界空间。地平线色调和距离雾连接这些层次。本项目不需要把每一层背景都制作成 Blender 模型：是否建模取决于该层是否需要可辨识轮廓、遮挡和视差。全景适合天空，三维地形负责空间关系，扫描贴图负责表面细节。

上述选择是项目具体判断。实现依据分别参见 Three.js 的[背景与天空盒](https://threejs.org/manual/pages/backgrounds.html)、[雾](https://threejs.org/manual/pages/fog.html)及 [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html) 文档。

原始下载保存在 [`artifacts/scenery-upgrade/sources`](../artifacts/scenery-upgrade/sources)，[`download-assets.ps1`](../artifacts/scenery-upgrade/download-assets.ps1)先核对源文件 MD5，再转换尺寸与格式并记录输出 SHA-256。运行时从本地静态资源路径加载。WebP 压缩减少传输体积；解码后的纹理与 mipmap 仍占用 GPU 内存，不能用文件体积代表显存成本。

## 实现边界

场景由 `src/render/environment.ts`、`src/render/roadObjects.ts`、`src/render/surfaceTextures.ts` 和 `src/render/engine.ts` 组织。三维渲染与 Rapier 二维物理解耦：路面顶点继续来自既定物理采样，倒角、边唇、封盖和五金位于行驶表面以外或下方；装饰不修改路线、碰撞形状、驾驶数值与关卡状态。

重复建筑零件共享几何体和材质并实例化。道路物体按同一刚体内的材质合并几何，保留独立活动部件与拾取动画，不能跨越不同运动对象合批。此方法与 Three.js [合并大量对象](https://threejs.org/manual/pages/optimize-lots-of-objects.html)的建议一致，实际收益仍以本项目浏览器统计为准。场景销毁释放几何体、材质和贴图，异步贴图回调也应尊重销毁状态。当前继续使用既有渲染器、质量档位与静态部署方式。

## 浏览器证据与验收限制

当前证据位于 [`artifacts/scenery-upgrade/reviewed`](../artifacts/scenery-upgrade/reviewed)：桌面 1440×900 与模拟手机横屏 844×390 的十二张实际 Chromium 截图，覆盖沙漠事故车、拖车、实验室厢式车、升降门、峡谷与货运平台；[`reviewed/results.json`](../artifacts/scenery-upgrade/reviewed/results.json)的页面错误和失败请求列表均为空。同视角的较早截图保留在 `final/`，便于核对审查前状态。

同场景桌面对照来自 [`before/results.json`](../artifacts/scenery-upgrade/before/results.json) 与最终结果：

| 场景 | 调整前绘制调用 | 当前绘制调用 |
| --- | ---: | ---: |
| 沙漠事故车 | 176 | 134 |
| 沙漠拖车 | 271 | 227 |
| 实验室厢式车 | 167 | 125 |
| 实验室升降门 | 152 | 119 |
| 峡谷 | 189 | 132 |
| 货运平台 | 386 | 147 |

当前采样约为 37.1 万至 50.7 万三角形。合批降低了这些采样位置的绘制调用，仍需结合三角形、透明层、阴影和纹理成本评估整体负担。采集包含重放开销与并行运行，记录的 FPS 不作为性能验收依据。

当前验证包括：53 项单元测试通过、生产构建通过（保留既有大包体警告）、既有玩法与修订浏览器套件共 6 项通过，以及环境浏览器回归 2 项通过；后者检查升降门位置、事故车外壳上边界和轮胎接地点。[`production-smoke.json`](../artifacts/scenery-upgrade/production-smoke.json)记录了生产预览中的桌面与模拟移动端加载和驾驶检查：页面错误与请求失败为空，十张本地贴图已加载，生产页面未暴露调试入口。资源加载成功不代表每张贴图均参与当前着色。

这些证据支持当前 Chromium 场景与部署资源的检查结果。[独立美术复核](../artifacts/scenery-upgrade/finish-review.md)给出 SHIP，范围仅为本轮场景增量交付：事故车接地与自然材质投影两项 P2 已关闭。地貌层带与沙地平铺重复仍是质量限制；真实手机 GPU、iOS 浏览器、长时间运行稳定性及完整商业美术验收仍未完成。CC0 来源记录解决上述资源的许可溯源，不替代全项目依赖、品牌及其他资产的发行核查。
